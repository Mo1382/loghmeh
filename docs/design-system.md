# Loqmeh — Design System (Desktop)

استخراج‌شده از فایل Figma **Loghmeh-final-1** (صفحه‌ی `✨ | UI Design`)، بر اساس بررسی مستقیم فریم‌های دسکتاپ (`desktop-home-not-authenticated`، `desktop-recipe-detail` و بخش `Authentication`) و متغیرهای طراحی (Figma Variables) تعریف‌شده در فایل.

> این سند پایه‌ی تصمیمات UI برای پیاده‌سازی در Tailwind/shadcn (طبق `architecture.md` §2) است. اگر بعداً کامپوننت‌های بیشتری (فرم‌ها، حالت‌های خطا) بررسی بشن، این سند باید به‌روزرسانی بشه.

> **وضعیت فعلی:** این سند از طراحی Figma و CSS فعلی جمع‌بندی شده است. UI featureها هنوز در App Router پیاده‌سازی نشده‌اند؛ مقادیر مربوط به layout فعلاً design target هستند.

## ۱. رنگ‌ها (Color Tokens)

## ۲. تایپوگرافی

- **فونت اصلی:** `IRANSansX` (فارسی) — با وزن‌های `Light`، `Regular`، `Medium`، `DemiBold`
- **فونت اعداد:** `IRANSansXFaNum` — یک فونت جدا مخصوص **اعداد فارسی** (رتبه‌ها، شمارنده‌ها) که از فونت متن اصلی جداست؛ این تفکیک باید در پیاده‌سازی هم رعایت بشه
- **جهت متن:** تمام متن‌ها راست‌به‌چپ (`dir="auto"`, `text-right`)
- **Line-height:** غالباً `1.4` (استاندارد پروژه)

### مقیاس اندازه‌ی فونت (مشاهده‌شده در صفحه‌ی Home)

| اندازه | وزن                | کاربرد                                      |
| ------ | ------------------ | ------------------------------------------- |
| `26px` | DemiBold           | عنوان بخش‌ها («محبوب‌ترین دستور پخت‌ها»)    |
| `20px` | DemiBold           | عنوان کارت (نام دسته/نام کاربر)             |
| `18px` | Regular / Medium   | آیتم‌های ناوبری اصلی                        |
| `16px` | Regular / DemiBold | متن اینپوت جست‌وجو، لینک‌های «مشاهده»       |
| `14px` | Regular            | متن فوتر                                    |
| `13px` | Regular / Medium   | برچسب دسته‌بندی، آیتم‌های جست‌وجوی پیشنهادی |
| `12px` | Light / Medium     | متادیتا (تعداد دستور، امتیاز)               |
| `11px` | Light              | عنوان نقش کاربر (مثلاً «سر آشپز»)           |
| `10px` | Light              | برچسب‌های خیلی کوچک                         |

## ۳. فاصله‌گذاری، شعاع گوشه و سایه

### شعاع گوشه (Border Radius)

| مقدار                          | کاربرد                                                                           |
| ------------------------------ | -------------------------------------------------------------------------------- |
| `12px`                         | دکمه‌ها، اینپوت جست‌وجو، آیکون‌های کوچک                                          |
| `24px`                         | کارت‌ها (دسته‌بندی، رسپی، کاربر، دراپ‌داون جست‌وجو) — **رادیوس شاخص طراحی لقمه** |
| `20px` (پایین) / `24px` (بالا) | تصویر داخل کارت رسپی — گوشه‌ی نامتقارن، هماهنگ با گوشه‌ی خود کارت                |
| `100%` / `9999px`              | آواتارها (کاملاً گرد)                                                            |

### سایه (Shadow)

تمام کارت‌ها از یک سایه‌ی نرم و یکسان استفاده می‌کنن:

```css
box-shadow: 0px 4px 4px 0px rgba(230, 230, 230, 0.08);
```

این سایه خیلی ملایمه — بیشتر برای جدا کردن بصری کارت از پس‌زمینه‌ست تا افکت عمق واقعی.

### بردر

- بردر پیش‌فرض کارت‌ها: `1px solid` با `neutral/black-4` (`#F0F0F0`) یا `neutral/black-5` (`#D9D9D9`)
- بردر اینپوت در حالت focus: `1px solid primary-red/300` (`#f68787`)

### شبکه‌ی فاصله‌گذاری (Spacing Grid)

فاصله‌ها عمدتاً مضرب `4px` هستن. مقادیر اجرایی فعلی در `src/app/globals.css` برای فاصله‌ی کارت‌ها عبارت‌اند از: دسکتاپ افقی `32px` و عمودی `38px`، تبلت افقی `24px` و عمودی `28px`، و موبایل افقی/عمودی `16px`. مقادیر مشاهده‌شده در Figma باید با این tokenهای CSS تطبیق داده شوند.

## ۴. کامپوننت‌های شناسایی‌شده

### ۴.۱ ناوبری اصلی (Main Navigation)

- نوار بالای صفحه شامل: لوگو، سرچ‌بار، آیتم «ورود» (حالت مهمان)
- سایدبار عمودی سمت راست با آیتم‌ها: خانه، ذخیره‌شده‌ها، دستور پخت جدید، همه دستورها، دسته‌بندی‌ها، جامعه لقمه
- **حالت فعال:** پس‌زمینه‌ی قرمز (`primary-red/500`) با متن سفید و رادیوس `12px`؛ آیتم‌های غیرفعال فقط آیکون + متن `neutral/black-9`

### ۴.۲ کارت دسته‌بندی (Category Card)

- ابعاد: `236×116`، رادیوس `24px`، بردر `neutral/black-4`، سایه‌ی استاندارد
- محتوا: آیکون تصویری، عنوان (`20px` DemiBold)، تعداد دستور پخت (`12px` Light + عدد با فونت `IRANSansXFaNum`)، لینک «مشاهده» با شورون

### ۴.۳ کارت دستور پخت (Recipe Card)

- ابعاد: `236×411`، رادیوس `24px` (تصویر با گوشه‌ی نامتقارن ۲۴/۲۰)
- محتوا: تصویر پوستر، برچسب دسته (`13px`)، عنوان (`18px` DemiBold)، آواتار نویسنده، امتیاز (ستاره + عدد `12px`)، آیکون بوکمارک (بالا-چپ کارت)، لینک «مشاهده»

### ۴.۴ کارت کاربر/آشپز (User Card)

- ابعاد: `326×152`، چیدمان افقی، تصویر پروفایل سمت چپ (گوشه‌ی نامتقارن)، نام (`20px` DemiBold)، عنوان/نقش (`11px` Light)، تعداد دستور، امتیاز، لینک «مشاهده»

### ۴.۵ اینپوت جست‌وجو + دراپ‌داون پیشنهادها

- اینپوت: ارتفاع `48px`، رادیوس `12px`، آیکون ذره‌بین + دکمه‌ی پاک‌کردن (X)
- دراپ‌داون نتایج: کارت سفید با رادیوس `24px`، هر آیتم شامل تصویر بندانگشتی + عنوان + دسته + امتیاز + لینک «مشاهده»، جداکننده‌ی خط بین آیتم‌ها، فوتر «مشاهده همه نتایج»

### ۴.۶ دکمه‌ی CTA اصلی

- پس‌زمینه‌ی `primary-red/500`، متن سفید `18px` Medium، رادیوس `12px`، آیکون کنار متن (مثال: «دستور پخت جدید»)

### ۴.۷ نشانگر مرحله (Marker Navigation)

- برای فلوهای چندمرحله‌ای (مثلاً ثبت‌نام): دایره‌ی شماره‌دار (مثال «۰۱») + عنوان مرحله؛ حالت فعال با `primary-red/600`

### ۴.۸ لودینگ (Page Spinner)

- سه دایره‌ی هم‌ردیف (نقطه‌چین متحرک) برای نمایش وضعیت loading محتوای در حال بارگذاری (مثلاً بخش‌های Home Feed)

## ۵. اصول چیدمان (Layout Principles)

- **RTL کامل:** تمام چیدمان‌ها از راست به چپ‌اند؛ ناوبری اصلی سمت راست صفحه، محتوا از راست شروع می‌شه
- **گرید دسکتاپ:** عرض کانتینر اصلی محتوا `1120px` با یک ستون سایدبار جدا در سمت راست (مجموعاً بومی برای صفحات با عرض کامل `1440px`)
- **کارت‌محور:** تقریباً تمام واحدهای محتوایی (دسته، رسپی، کاربر، نتیجه‌ی جست‌وجو) در قالب «کارت» با رادیوس بزرگ (۲۴) و سایه‌ی ملایم یکسان ارائه می‌شن — این یک زبان طراحی ثابت در کل پروژه‌ست

## ۷. واکنش‌گرایی و نقاط شکست (Responsive Breakpoints)

سه نقطه‌ی شکست اصلی در فایل شناسایی شد (هر صفحه‌ی کلیدی—مثل Home—در هر سه سایز طراحی شده):

| Breakpoint | عرض کانواس                        |
| ---------- | --------------------------------- |
| Desktop    | `1440px` (کانتینر محتوا `1120px`) |
| Tablet     | `768px`                           |
| Mobile     | `412px`                           |

### ۷.۱ الگوی ناوبری بر اساس سایز صفحه — **مهم‌ترین تفاوت ساختاری**

| Breakpoint  | الگوی ناوبری                                                                                                                                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Desktop** | سایدبار عمودی کامل، ثابت سمت راست؛ هر آیتم آیکون + متن؛ آیتم فعال با پس‌زمینه‌ی قرمز                                                                                                                                                              |
| **Tablet**  | ناوبری جمع می‌شود به آیکون **همبرگر (align-justify)** در هدر؛ سرچ هم به یک آیکون کوچک تبدیل می‌شود (به‌جای اینپوت کامل)                                                                                                                           |
| **Mobile**  | یک **نوار ناوبری شناور پایین صفحه (Floating Bottom Nav)** ظاهر می‌شود: کپسول با پس‌زمینه‌ی تیره‌ی نیمه‌شفاف (`rgba(140,140,140,0.95)`)، رادیوس `24px`، ۵ آیتم شامل خانه، دسته‌بندی، **دستور جدید (وسط)**، ذخیره‌ها، پروفایل — آیکون‌ها و متن سفید |

> این یعنی کامپوننت ناوبری باید به‌عنوان **سه کامپوننت جدا** (`SidebarNav`, `DrawerNav` با تریگر همبرگری، `FloatingBottomNav`) پیاده بشه، نه یک کامپوننت با CSS ریسپانسیو ساده — چون الگوی تعاملی‌شون کاملاً فرق داره.

### ۷.۲ مقیاس‌بندی کارت‌ها

| المان                  | Desktop                                  | Tablet / Mobile                          |
| ---------------------- | ---------------------------------------- | ---------------------------------------- |
| کارت دسته‌بندی         | `236×116`، radius `24px`                 | `154×84`، radius `16px`                  |
| کارت دستور پخت         | `236×411`، radius `24px` (تصویر `24/20`) | `154×311`، radius `18px` (تصویر `18/14`) |
| آیکون بوکمارک روی کارت | `32px`                                   | `28px`                                   |

### ۷.۳ مقیاس تایپوگرافی بر اساس Breakpoint

**نکته‌ی کلیدی:** تایپوگرافی **داخل کارت‌ها** (دسته‌بندی، دستور پخت) بین Tablet و Mobile کاملاً یکسانه — چون هر دو از همون کامپوننت کارت (`154px` عرض) استفاده می‌کنن. فقط تایپوگرافی **سطح صفحه** (عنوان بخش‌ها، لینک «مشاهده همه») در سه سطح جدا کوچیک می‌شه.

**تایپوگرافی سطح صفحه (Page-level):**

| عنصر                            | Desktop                        | Tablet                            | Mobile                             |
| ------------------------------- | ------------------------------ | --------------------------------- | ---------------------------------- |
| عنوان بخش (مثل «محبوب‌ترین...») | `26px` DemiBold، بدون tracking | `20px` DemiBold، tracking `0.2px` | `15px` DemiBold، tracking `0.15px` |
| لینک «مشاهده همه»               | `16px` Regular                 | `12px` Regular، tracking `0.12px` | `9px` Light، tracking `0.09px`     |
| آیکون کنار «مشاهده همه»         | —                              | `17px`                            | `12px`                             |

**تایپوگرافی داخل کارت (Card-level) — مشترک بین Tablet و Mobile:**

| عنصر                        | Desktop         | Tablet = Mobile                                     |
| --------------------------- | --------------- | --------------------------------------------------- |
| عنوان کارت دسته‌بندی        | `20px` DemiBold | `15px` DemiBold                                     |
| تعداد دستور (متادیتای دسته) | —               | `8px` Light                                         |
| عنوان کارت دستور پخت        | `18px` DemiBold | `14px` DemiBold                                     |

### ۷.۴ الگوی چیدمان محتوا

- **Desktop:** کارت‌ها در یک گرید ثابت (چند ستونه) چیده می‌شن؛ کل عرض محتوا در یک صفحه دیده می‌شه.
- **Tablet / Mobile:** از یک **کروسل افقی با اسکرول** استفاده می‌شه — کارت بعدی/قبلی کمی از لبه‌ی صفحه بیرون می‌زند («peek carousel») تا کاربر متوجه‌ی قابلیت اسکرول بشه. این الگو هم در بخش دسته‌بندی‌ها و هم دستور‌های محبوب دیده شد.

### ۷.۵ نکات خاص هر Breakpoint

**Tablet**

- ارتفاع هدر کمی کمتر از دسکتاپ
- سرچ به آیکون تبدیل می‌شه (به‌جای اینپوت باز)؛ روی کلیک احتمالاً باز می‌شه

**Mobile**

- ارتفاع هدر: `72px` با `border-bottom`
- دراپ‌داون نتایج جست‌وجو **تمام‌عرض** (full-width overlay) درست زیر نوار جست‌وجو، نه یک باکس شناور کوچک
- نوار کپی‌رایت فوتر جمع‌وجورتر: ارتفاع `37px`، فونت `9px`
- دکمه‌ی مرکزی نوار پایین («دستور پخت جدید») به‌احتمال زیاد نقش FAB (Floating Action Button) رو بازی می‌کنه — از بقیه‌ی آیتم‌ها بصری متمایزتره

## ⚠️ محدودیت‌های این استخراج

این سند بر اساس بررسی صفحه‌ی **Home در هر سه سایز (Desktop/Tablet/Mobile)** + بخش Authentication ساخته شده. موارد زیر هنوز بررسی نشدن و بهتره جداگانه چک بشن:

- حالت‌های فرم (اینپوت متن معمولی، select، textarea، checkbox/radio) در هر سه سایز
- حالت‌های خطا (error state رنگ قرمز روی فرم‌ها)
- دکمه‌های ثانویه/outline/disabled
- محتوای دقیق منوی Drawer در حالت Tablet (فقط آیکون همبرگر دیده شد، خود منوی باز شده بررسی نشد)
- Dark mode (طبق روردمپ v2 هنوز در این فایل طراحی نشده)

اگه بخوای می‌تونم بخش **Authentication** یا **System** رو هم در هر سه سایز بررسی کنم تا کامپوننت‌های فرم و حالت خطا رو هم به این سند اضافه کنم.
